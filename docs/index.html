Overview

simple_smt is a native Eiffel binding to Z3, Microsoft Research's Satisfiability-Modulo-Theories solver. Build logical formulas over integers, reals, and booleans with a fluent API; decide satisfiability; extract satisfying models; and — the headline — prove that a formula holds for all values, or get a concrete counter-model when it does not.

It is a 100%-Eiffel facade over Z3's C API via inline-C externals; Z3 is the only external dependency, bundled (MIT) and linked directly. No Boogie, no external process, no proprietary component.

Part of the Simple Eiffel ecosystem.

It proves real things

create smt.make
x := smt.int_const ("x"); zero := smt.int_value (0); one := smt.int_value (1)

-- Prove a theorem (valid for every x):  x >= 0  implies  x + 1 > 0
smt.prove (x.at_least (zero).entails (x.plus (one).greater (zero)))   -- True

-- Refute a non-theorem, with a witness:
smt.refutation (x.greater (zero))                                     -- "x -> 0"

-- Solve a constraint and read the model:
smt.assume (x.greater (smt.int_value (5)))
smt.assume (x.less (smt.int_value (8)))
smt.model_value (x)                                                   -- "6"

Verified, not a toy

The 56-test suite includes 35 real-world scenarios mined from actual simple_* contracts (fraction ordering, decimal cent-splitting, adler32 mod-65521 bounds, cache capacity, base64/datetime arithmetic, pigeonhole and graph coloring), non-vacuity detection, and a reproduction of the AutoProof ACCOUNT tutorial: simple_smt independently refutes the same three verification conditions the MIT verifier flags, then proves the fixed versions.

Features

  • Sorts: integers, reals, booleans
  • Operators: + - *, mod, div, unary minus; < <= > >= =; and or not implies xor iff ite; pairwise distinct
  • prove (validity via negation-unsat, non-mutating), refutation (counter-model), is_satisfiable, model_value
  • Convenience: maximum, absolute, all_distinct
  • push/pop/reset, SMT-LIB2 emission
  • Lazy memoized decisions (no redundant solver calls), full contracts, void-safe, SCOOP-compatible

Why it exists

simple_smt is the mechanical core — the trusted "dispose" in a propose/dispose loop — under contract verification, non-vacuity checking, and specification synthesis. Z3 is the trusted oracle; simple_smt's own claim is only faithful translation of the Eiffel expression tree into Z3's AST, grounded by a suite that proves known theorems and refutes known non-theorems.
